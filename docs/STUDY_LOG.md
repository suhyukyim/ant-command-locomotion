## 0. 프로젝트 한 줄 요약

MuJoCo Ant(4족 로봇)에게 **"이 방향, 이 속도, 이 에너지 수준으로 걸어"** 라는 명령을 주고,
**정책(신경망) 하나**가 모든 명령을 따르도록 **PPO**로 학습한다. 모션 데이터 없이 보상만으로 학습한다.

- 모션 없이 학습 + 에너지 수준 + 경로 추종 → FreeMusco 축소판
- 키보드 실시간 조종 → PhysicsFC 축소판

### 파일별 역할

| 파일 | 역할 |
|---|---|
| `envs/command_ant.py` | **핵심.** Ant-v5 래퍼. 관측에 명령 3개(몸 기준 속도 2 + 에너지 1)를 붙이고 보상을 직접 계산. 학습 중엔 명령을 랜덤으로 뽑고 250스텝마다 바꿈 |
| `train.py` | PPO 학습. 병렬 환경 8개, 관측·보상 정규화(VecNormalize), 체크포인트, 텐서보드 로그 |
| `policy_utils.py` | 학습된 모델 + **정규화 통계**를 같이 불러와서 `Policy.act(obs)` 제공 |
| `evaluate.py` | 8방향 × 2속도 명령 추종 그래프(`tracking.png`), 에너지 수준별 그래프(`energy.png`), `summary.json` |
| `path_follow.py` | 웨이포인트 경로 추종. 상위 로직이 방향 명령을 주고 하위 정책이 걷는 계층 구조 |
| `keyboard_demo.py` | 터미널 w/a/s/d로 실시간 조종 |

흐름: `command_ant.py`(환경·보상) → `train.py`(학습) → `policy_utils.py`(불러오기) → `evaluate` / `path_follow` / `keyboard_demo`(검증·데모)

### "학습"이 뭘 하는 건지

- 정책 = 신경망. `관측(105 + 명령 3) → [신경망] → 행동(관절 8개에 줄 힘)`, 0.05초마다
- 학습 = 신경망 가중치를 조금씩 고치는 것
- 고치는 방향: 점수(보상)를 많이 받은 행동은 더 자주, 적게 받은 행동은 덜 하도록
- **보상 = 어느 쪽으로 고칠지 알려주는 나침반**

## 1. 관측에 명령을 넣는 이유

- 정책은 `행동 = π(관측)`인 함수. 판단에 쓸 수 있는 건 **관측에 들어 있는 것뿐**. 보상은 학습 때 점수로만 쓰이고 입력이 아니다.
- 명령을 관측에 안 넣으면: "앞으로 1 m/s"와 "뒤로 1 m/s"에서 입력이 똑같음 → **같은 행동**밖에 못 함
- 보상은 정반대 행동을 원하니, 정책은 **모든 명령에서 평균적으로 손해가 적은 행동**으로 수렴 → 명령 방향이 360° 고르게 뽑히니 평균 ≈ 0 → **제자리 버티기**

## 2. 명령을 몸 기준으로 회전 (`command_ant.py` `_command_in_body_frame`)

- 같은 "동쪽으로 걸어"라도 Ant가 동쪽을 보면 **앞으로**, 북쪽을 보면 **오른쪽으로** 걸어야 함
- 다리 움직임은 몸 기준(앞/뒤/왼/오)으로 생각하는 게 쉬움
- 그래서 명령 **값(화살표)** 을 몸통 yaw만큼 **반대로(`-yaw`)** 돌려서 넘겨줌. Ant가 도는 게 아니라 **값이 회전**하는 것
  - 예: Ant가 북쪽(yaw = +90°)을 봄. 동쪽 명령(0°) − 90° = **−90° = 오른쪽**
  - 각도 규칙: + = 반시계(왼쪽), − = 시계(오른쪽), 앞 = 0°, 뒤 = 180°
- 이유: 회전 공식(cos, sin, 곱셈)을 신경망이 시행착오로 배우게 하면 데이터와 시간이 더 듦. 이미 아는 공식은 사람이 넣고, 신경망은 **걷기에만 집중**

## 3. 속도 추종 보상과 v2가 "버티기만" 배운 이유

```
reward = 2.0 · tracking + 1.0 · alive − ctrl_w · effort
tracking = exp(−오차² / sigma),  sigma = 0.25
```

### sigma = 0.25일 때 한 스텝 점수 (명령 1 m/s, 제어 비용 무시)

| 상황 | 오차² | tracking | 점수 |
|---|---|---|---|
| 가만히 서 있기 | 1 | exp(−4) ≈ 0.018 | ≈ 1.04 |
| 0.1 m/s로 조금 움직이기 | 0.81 | exp(−3.24) ≈ 0.039 | ≈ 1.078 |
| 0.5 m/s로 어설프게 | 0.25 | exp(−1) ≈ 0.368 | ≈ 1.736 |
| 완벽하게 1 m/s | 0 | exp(0) = 1 | 3.0 |

- 학습 초반 Ant는 0.5 m/s로 걷는 법을 **모름**. 서 있는 곳에서 **조금씩** 바꿔 보는 수밖에 없음
- 서 있기 → 조금 움직이기: 이득이 **스텝당 0.04점뿐**
- 그런데 움직이다 넘어지면 남은 버티기 점수(스텝당 1점)를 다 잃음
- → 서 있는 곳 주변이 **평지**라서 방향 신호가 잡음에 묻힘. 왔다 갔다만 하다가 서 있는 쪽으로 끌려옴 = **국소 최적**
- v2는 학습률이 3e-4 → 0으로 줄어들어서, 후반엔 보폭까지 작아져 더 못 빠져나옴

### sigma = 1.0으로 바꾸면

| 상황 | 오차² ÷ 1.0 | tracking | 점수 |
|---|---|---|---|
| 가만히 서 있기 | 1 | 0.368 | 1.736 |
| 0.1 m/s로 움직이기 | 0.81 | 0.445 | 1.89 |

- 차이 ≈ 0.154 → sigma 0.25일 때(0.04)의 **약 4배** → 평지가 **비탈**이 됨 → 첫걸음 신호가 잡음을 이김
- 중요한 건 점수의 절대 크기가 아니라 **"조금 바꿨을 때의 차이(기울기)"**

### sigma 트레이드오프

| sigma | 초반 (서 있기 → 걷기) | 후반 (대충 → 정확히) |
|---|---|---|
| 작게 (0.25) | 평지 → 시작 못 함 | 비탈 → 정밀하게 맞춤 |
| 크게 (1.0) | 비탈 → 시작 쉬움 | 평지 → 대충 걷기에 만족 (1 m/s: 3.0 vs 0.8 m/s: 2.92) |

### 양쪽 장점을 다 얻는 방법

1. **커리큘럼:** sigma를 처음엔 크게, 나중에 작게. 전환 기준은 시간보다 **성적**(예: 평균 오차 < 0.3 m/s)이 덜 애매함
2. **두 항 더하기:** `exp(−오차²/1.0) + exp(−오차²/0.25)`. 멀리선 1.0 항, 가까이선 0.25 항이 비탈 역할
3. ✗ **구간 나누기**(오차² ≥ 0.5면 sigma 1.0, 아니면 0.25): 경계에서 0.51 → 0.49로 **가까워졌는데 점수가 0.60 → 0.14로 떨어짐** = 절벽

- 어떤 방법이든 정해야 할 숫자(하이퍼파라미터)가 생김 → 정답은 없고 **하나씩 바꿔서 비교**해야 함

### 보상 설계 원칙: 단조성

- 두 항 더하기: 오차가 줄면 두 항 **모두 커짐** → 합도 반드시 커짐 (단조)
- **보상이 단조여야 "명령에 가까워지는 방향 = 점수가 오르는 방향"이 항상 일치해서 학습이 헷갈리지 않는다**

## 4. 에너지 수준 (제어 비용)

```
ctrl_w = 0.02 + (1 − e) · (0.25 − 0.02)
effort = Σ action²
```

- 에너지 수준 e는 실제 배터리가 아니라 **"걷는 스타일" 다이얼**. 속도는 같고 걷는 **방식**만 달라짐 (FreeMusco 아이디어)

| e | ctrl_w | effort 4일 때 깎이는 점수 |
|---|---|---|
| 1 (마음껏) | 0.02 | 0.08 |
| 0 (아껴라) | 0.25 | 1.00 (= 버티기 점수 전부) |

- e = 0이면 힘을 **덜** 쓰는 걸음이 유리
- e도 **관측에 넣어야** 함 (1번과 같은 이유: 안 넣으면 상황 구분 불가 → 평균으로 걸음)
- 학습 중 e는 에피소드마다 0~1 랜덤 → 모든 다이얼 위치를 경험
- `evaluate.py`의 `energy.png`, 학습이 잘 됐다면:
  - **제어 노력:** e가 0 → 1로 갈수록 **올라감**
  - **실제 속도:** e와 상관없이 명령(1 m/s) 가로선에 **평평하게** 붙어 있음 (현실에선 e = 0 쪽이 살짝 처질 수 있음 = 힘 아끼기 vs 속도 맞추기 줄다리기)
  - 지금 v2는 버티기만 배워서 속도 선이 0 근처일 가능성 높음 → [3]에서 직접 돌려서 확인

## 5. [2] PPO가 뭔지 (확률비와 clip)

- v2는 환경 8개 × 1024 = **8192스텝**을 고치기 전 정책으로 모으고, 그 데이터로 5에폭 반복해서 고친다 (`train.py:88-99`)
- 정책이 너무 바뀌면 옛 데이터는 쓸모없어진다
  - **상황이 다르다:** 걸음이 바뀌면 도착하는 상황 자체가 달라짐
  - **행동이 다르다:** 옛 기록엔 A의 점수만 있음. 새 정책이 B를 하면 B가 좋은지는 새로 해 봐야 앎 (식당 리뷰: 김치찌개 리뷰로 된장찌개 맛은 모름)
- 매번 새로 모으면 정확하지만 너무 느림 → PPO는 **데이터를 재사용하되 바뀌는 폭만 제한**
- 바뀐 정도 = **확률비 r = 새 정책 확률 / 옛 정책 확률** (예: 0.5 / 0.2 = 2.5배). r = 1이면 그대로
- `clip_range=0.2` → r은 **0.8 ~ 1.2**만 인정 (0.2는 한쪽 폭)

| 상황 | r이 범위를 넘으면 |
|---|---|
| 좋은 행동, 확률 올리는 중 | 1.2에서 **더 안 올림** (힘 = 0) |
| 나쁜 행동, 확률 내리는 중 | 0.8에서 **더 안 내림** |

- 버리거나 저장하는 게 아니다. 그 데이터가 미는 힘만 0이 되고, 범위 안 데이터는 계속 학습에 쓰임 (보너스 상한제)

> 내 말로: **정책이 너무 많이 바뀌면 옛 정책으로 모은 데이터는 새 정책의 상황·행동을 반영 못 해서 쓸모없어진다. 그래서 PPO는 확률비 r을 0.8~1.2로 클리핑해서, 한 번 모은 데이터로 여러 번 고쳐도 정책이 크게 바뀌지 않게 한다.**

## 6. [2] v1이 무너진 이유 (KL 폭발)과 v2 수정

| | 한 번 모은 데이터로 고친 횟수 | KL |
|---|---|---|
| v1 | 미니배치 48 × 10에폭 = **480번** | **4.11 (폭발)** |
| v2 | 미니배치 4 × 5에폭 = **20번** | 정상 |

### 가중치
- 신경망 = 곱하고 더하는 계산. 곱하는 숫자들이 **가중치** (정책 `pi=[256, 256]` → 약 9.6만 개)
- **모든 상황이 같은 가중치를 함께 쓴다** → 한 상황을 위해 고치면 다른 상황 행동도 바뀜 (요리사 한 명의 소금 습관)

### clip이 있는데 왜 폭발했나
- clip은 데이터 X가 **미는 힘만 0**으로 만든다. "되돌려"는 안 함
- 범위 안 데이터 Y가 계속 가중치를 고치면, 가중치를 같이 쓰는 X의 r도 **계속 밀려남** (1.2 넘어 3, 5로)
- 20번이면 조금 밀리고 끝, **480번이면 밀림이 쌓여** 정책 전체가 옛 정책에서 멀어짐

### v2의 수정 3가지
| 수정 | 효과 |
|---|---|
| 480 → 20번 | 밀림이 쌓일 기회 자체를 줄임 |
| `target_kl=0.02` (`train.py:98`) | **KL = 데이터 전체 평균 변화량** (r은 데이터 하나). 커지면 남은 에폭을 **건너뛰고** 새 데이터를 모으러 감 (SB3는 실제로 1.5 × 0.02 = 0.03 기준) |
| 학습률 3e-4 → 0 (`train.py:99`) | 보폭을 줄여 후반 안정 |

- KL은 데이터를 골라 버리는 게 아니다. 이 데이터로 **고치는 걸 멈추는** 신호
- PPO 반복: ① 지금 정책으로 모으기 → ② 여러 번 고치기 (clip, KL 넘으면 중단) → ① 다시. (가)의 정확함 + (나)의 효율
- v1에 `target_kl`이 있었다면 앞의 몇 번만 고치고 멈춰서 4.11까지 못 갔음

### 학습률 감소의 부작용
- 평지(국소 최적)를 빠져나오려면 **보폭이 커야** 유리 (눈 가리고 더듬기: 1cm 걸음은 계속 평지, 1m 걸음은 언젠가 경사를 느낌)
- 학습률 → 0이면 사실상 제자리 → v2는 sigma 0.25 평지에 갇힌 데다 **빠져나올 마지막 기회마저 사라짐**

| 학습률 | 장점 | 단점 |
|---|---|---|
| 크게 유지 | 평지 탈출 기회 | 불안정할 수 있음 |
| 0으로 감소 | 후반 안정 | 평지에 갇히면 못 나옴 |

## 7. [3] 정규화 통계를 왜 같이 불러오나

| 5 | 0.5 | 5 |
| 20 | 2.0 | 20 |

## 10. [5] v4 → v5: 왜 tanh인가 ★

### 문제 (v4)
- 정책은 행동을 **확률 분포**로 낸다: u ~ N(μ, σ²). 환경엔 `clip(u, −1, 1)`이 들어간다.
- v4는 관절 평균 μ의 **69%가 ±1 밖**이었다 (예: μ = 2.9, σ = 0.7).

| | μ = 2.9인 관절에서 일어나는 일 |
|---|---|
| 노이즈 끔 (행동 = μ) | 매 스텝 2.9 → 잘려서 1.0. 늘 같은 값 → **굳은 자세** |
| 노이즈 켬 (행동 = μ + 노이즈) | 거의 늘 잘림. 경계 근처 관절만 안팎을 오가며 **떨림** → 그 떨림이 몸을 밀어냄 |

- 잘린 영역에서는 1.2를 뽑든 2.0을 뽑든 환경에선 똑같이 1.0 → **보상이 차이를 못 알려 줌** → 학습 신호가 없음.
- 그래서 정책은 "쓸 수 있는 평균 행동"이 아니라 "노이즈에 기대는 분포"를 배웠다.

### 수정 (v5)
- a = tanh(u). tanh는 어떤 u든 (−1, 1) 안으로 **부드럽게** 눌러 넣는다. 2.0과 1.2는 tanh 뒤에도 다른 값 → 보상이 차이를 구분할 수 있음.
- 확률 계산엔 보정이 필요: log π(a) = log N(u) − Σ log(1 − tanh(u)²) (`squashed_policy.py`).
- **v4와 v5는 행동 출력 구조만 다르다** → 한 번에 하나만 바꾼 비교.

| | v4 | v5 |
|---|---|---|
| 포화 비율 | 0.69 | 0.00 |
| 노이즈 끔 속도 | 0.011 m/s | 0.251 m/s |
| 노이즈 끔에서 움직인 명령 | 1 / 16 | 14 / 16 |

## 11. [5] 기준선 보상 표 읽기 ★

`python baseline_rewards.py` (README "기준선 보상 비교"). v6B 보상, 학습 때와 같은 랜덤 명령, 1000스텝 × 8 에피소드.

| 정책 | 에피소드 보상 | 버틴 스텝 | 평균 토크 |
|---|---|---|---|

읽는 순서:
1. **왜 "노이즈 켬" 줄이 중요한가.** PPO는 학습 중 노이즈를 켠 채로 행동하고 그 보상을 올린다. 그러니 PPO 입장의 성적은 2933이다 (학습 로그 `ep_rew_mean` 2930과 맞음).
2. **2933 < 3842.** 660만 스텝을 학습했는데, 손으로 짠 "서 있기"보다 자기 점수가 낮다. 명령을 잘 따르면 5000점 이상도 가능하다. → **보상이 막고 있는 게 아니라 PPO가 거기까지 못 가는 것.** 그래서 페널티를 더 붙이는 건 핵심을 비껴간다.
3. **단위 감각.** Ant는 0.91 kg(무게 약 8.9 N). 행동 1.0 = 150 N·m. 서 있는 데 0.5 N·m면 된다. 학습 초기 노이즈(σ 1.0)는 평균 84 N·m의 무작위 토크 → 평균 164스텝 만에 넘어진다.
4. **마지막 두 줄이 핵심 비교.** 노이즈 크기는 같고(σ 1.0) **행동의 뜻만** 다르다. 토크로 해석하면 넘어지고(352), 목표 각도로 해석하면 학습 전부터 선다(3715).
5. **가설:** 정책은 먼저 "자기 노이즈에 안 넘어지는 법"을 배웠고, 관절을 한계로 밀어 버티는 게 그 답이었다 (12번에서 8개 관절 모두 한계로 미는 것과 맞음). **아직 학습으로 확인하지 않았다.**
