# v9 설계: 디딤 보상 (학습 전에 고정, 2026-11-11)

## 1. 왜

v8([`V8_DESIGN.md`](V8_DESIGN.md), README v8 절)에서 다섯 갈래 모두 "걷는다" 판정을 받지 못했다.
PD와 작은 탐색 노이즈로 관절 한계 문제는 사라졌지만, 하중 디딤 지속은 모든 갈래가 0.026~0.028 s였다(합격선 0.10 s).

`reward_compare.py`로 지금 보상(v6B)이 디딤을 어떻게 보는지 쟀다(3~10초 구간, 스텝당).

| | 0.5 m/s 앞 | 1.0 m/s 앞 |
| --- | --- | --- |
| CMA 디딤 패턴 (디딤 0.10 s, PD 사전 시험 합격) | 5.14 | 3.64 |
| 학습된 v8 B (디딤 0.03 s) | 4.94 | 3.73 |
| 서 있기 | 4.89 | 2.84 |

**지금 보상은 디딤을 손해로도 이득으로도 보지 않는다.** 점수 차이는 거의 속도가 만든다. 그래서 v9는 디딤에 직접 보상 기울기를 준다.

## 2. 바꾸는 것: 디딤 보상 (`envs/stance.py`)

물리 스텝마다 발별 하중 디딤(발 하나의 F_z ≥ 0.25 mg, v8 측정과 같은 기준)을 추적한다. 디딤이 끝나는(발이 떨어지는) 순간 아래 보너스를 준다.

    보너스 = clip(디딤 시간 − 0.05 s, 0, 0.20 s) × clip(디딤 동안 평균 명령 방향 몸통 속도 / |명령|, 0, 1)
    보상 += stance_weight × 보너스

보너스를 이렇게 정한 이유는 우회로를 막기 위해서다.
- 0.03 s짜리 튀는 접촉은 0이다. v8의 모든 정책이 받는 값이 정확히 0이었다(아래 사전 시험).
- 서 있기는 발을 떼지 않으니 0이다.
- 제자리걸음, 뒤로 가기, 서기 명령(명령 0)도 0이다.
- 오래 붙이고 있어도 0.25 s에서 자른다.

나머지 보상은 v8 B와 같다(v6B: tanh, 추종 σ 1.0 · 가중치 5, 관절 한계 범위 끝 20% · 가중치 1.5, PD kp 120 · kd 21).
가중치 0이면 v8과 비트 단위로 같다(`tests/test_stance.py`).

## 3. 갈래

| 갈래 | 설정 | 비교 |
| --- | --- | --- |
| B (v8, 이미 있음) | PD, K0 | 기준 |
| **F** | B + 디딤 보상 (가중치 40) | B ↔ F: 디딤 보상의 효과 |
| **H** | F + 초기 탐색 σ 0.1 (`--log-std-init ln 0.1`) | F ↔ H: v8에서 가장 나았던 작은 노이즈를 PD에 얹은 효과 |

학습 seed 0, 1, 2 × (500만 스텝 + 학습률 1e-4 고정 이어 학습 160만 스텝), v8과 같다. 실행은 `KP=120 KD=21 bash run_v9.sh`이다.

## 4. 사전 시험으로 정한 가중치 (`runs/v9_pretest/`)

가중치를 곱하기 전 3~10초 구간 스텝당 값이다. 기준 B는 v8 seed 3개, 명령은 0.5 m/s와 1.0 m/s 앞이다.

| | 디딤 보너스 | 하중 발 미끄러짐 속도² |
| --- | --- | --- |
| CMA 디딤 패턴 | 0.016~0.032 | 0.12~0.15 |
| v8 B | 0.000 | 0.27~0.30 |
| 서 있기 | 0 | 0 |

- **디딤 가중치:** 후보 10, 20, 40 중 두 명령 모두에서 CMA 패턴(kp120 재시작 2)이 B(노이즈 끔·켬 중 높은 쪽)보다 스텝당 0.25 이상 높아지는 가장 작은 값을 고른다. 1.0 m/s 앞 명령의 차이는 아래와 같다.
  - 10: +0.07, 미달
  - 20: +0.22, 미달. 손 계산으로는 +0.25였지만 실측에서 못 넘었다.
  - **40: +0.54, 통과.** 0.5 m/s 명령에서는 +1.42다.
  - 측정 파일은 `runs/v9_pretest/reward_compare_st{10,20,40}_sl0.json`이다.
- **미끄러짐 페널티는 넣지 않는다.** 0.5 m/s에서 서 있기(4.89)가 B(4.94)보다 0.05밖에 낮지 않다. 가중치 0.17만 넘어도 서 있기가 B보다 높아져, v7(발목 잠금)과 같은 우회로를 연다. 그 자리에 갈래 H를 둔다.

## 5. 합격선: v8과 같음 (`V8_DESIGN.md` 10절, 바꾸지 않는다)

판정은 노이즈 끔으로 한다. 추종 성공률 ≥ 0.5, 속도 ≥ 0.40, 이동 성공률 ≥ 0.95, 영구 굳음 0, 디딤 지속 ≥ 0.10 s, 하중 시간 비율 ≥ 0.30,
네 발 공중 ≤ 0.20, 미끄러짐 ≤ 0.50, 관절 한계 ≤ 0.20, 넘어짐 ≤ 0.02.
노이즈 켬 보조 기준도 v8과 같다(넘어짐 ≤ 0.05, 이동 ≥ 0.90, 굳음 0, 속도 ≥ 끔의 70%, 디딤 ≥ 0.07 s).
판정은 `runs/repeated_v9/judgement.md`에 나온다(`v8_judge.py --configs main_v8Bb main_v9Fb main_v9Hb`).

## 6. 결과 해석 (학습 전에 적어 둔다)

| 결과 | 읽는 법 |
| --- | --- |
| F 또는 H가 걷는다 | 디딤에 보상 기울기가 없던 것이 병목이었다 |
| 디딤 지속은 늘었지만 속도·추종이 B보다 떨어졌다 | 디딤과 추진이 아직 맞바뀐다. 디딤 보상 가중치나 게이트를 다시 본다 |
| 디딤 지속이 B와 같다 (0.03 s 근처) | 보너스가 학습 중 거의 0이라 기울기가 생기지 않았다(탐색 문제). 텐서보드 `command/stance_bonus`로 확인한다 |
| 서 있거나 제자리에서 디딘다 | 게이트가 막지 못한 우회로. 표에 끼워 넣지 않고 그대로 적는다 |
| H만 걷는다 | 디딤 보상과 작은 노이즈가 함께 필요했다 |

한 번의 배치로 원인을 확정하지 않는다. 결과가 나빠도 합격선을 낮추지 않는다.
